# 代码审查与安全修复记录

**审查日期**：2026-07-06
**审查范围**：后端认证与中间件、后端数据层与文件上传、前端安全与质量、部署/CI/数据库/配置

## 概述

项目收尾阶段全面 review，发现并修复 6 个 Critical 安全问题和一批 Important 问题。前端审查未发现 Critical/Important 安全问题。所有修复通过 `go build/vet` + `tsc --noEmit` + `vite build` 验证。

## Critical 修复（6 个）

### 1. 草稿泄露

**位置**：
- `backend/internal/handler/blog/blog_handler.go`（List / GetByID / GetBySlug / GetSummary）
- `backend/internal/service/blog/blog_service.go`（GetByID / GetBySlug / GetSummary）
- `backend/internal/repository/blog/blog_repo.go`（getOne 不检查 status）

**问题**：
- `GET /blogs` 在 OptionalAuth 中间件下，任何人（含未登录）传 `?status=draft` 可列出草稿
- GetByID/GetBySlug 调 `repo.getOne`（不检查 status），凭 ID/slug 可读草稿完整内容（content_html）
- GetSummary 注释声称有 visibility check，但实际调 GetByID（不检查 status），草稿的 AI 摘要也泄露 —— 这个 check 是假的

**影响**：未发布的草稿博客内容、标题、AI 摘要对外泄露。

**修复**：
- `blog_service.go` 新增 `canViewBlog(blog, currentUserID, role)`：published 公开；draft 需 `currentUserID == blog.UserID` 或 `role == "admin"`
- GetByID/GetBySlug/GetSummary 接口加 `role` 参数，获取 blog 后调 `canViewBlog`，不满足返回 `ErrBlogNotFound`
- `blog_handler.go` 新增 `getRole(c)` helper；List 中非 admin 强制 `status="published"`；GetByID/GetBySlug/GetSummary 传 `getRole(c)`
- Update/GenerateSummary 内部调 `repo.GetByID`（admin 上下文），不受影响

### 2. admin 默认密码 admin123

**位置**：`backend/cmd/server/main.go:68-71`

**问题**：`ADMIN_PASSWORD` 环境变量未设置时 fallback 为 `"admin123"`（代码明文可见）。`deploy/docker-compose.yml` 中 `ADMIN_PASSWORD: ${ADMIN_PASSWORD:-}` 默认空，触发此 fallback。VPS 部署若 `.env` 遗漏，管理员用弱密码。

**修复**：release 模式（`SERVER_MODE=release`）下 `ADMIN_PASSWORD` 未设置则 `log.Fatal` 退出；debug 模式保留 dev 默认（本地开发依赖）。

### 3. refresh token 无轮转/重放

**位置**：`backend/internal/service/auth/auth_service.go`（RefreshToken）

**问题**：原 RefreshToken 验证 JWT 签名后直接 `generateTokens`，旧 refresh token 不失效，可无限重放。攻击者窃取 refresh token 后可在 7 天有效期内无限刷新冒充用户。

**修复**：
- 新增迁移 013：`users` 表加 `refresh_token_hash VARCHAR(64)` 列
- `user_repo` 新增 `GetRefreshTokenHash` / `UpdateRefreshTokenHash` / `ClearRefreshTokenHash`
- `auth_service` 新增 `hashToken`（SHA-256）；RefreshToken 校验 `storedHash` 匹配后轮转（更新 hash 为新 token 的 hash），旧 token hash 不匹配被拒
- Register/Login/GitHubCallback 生成 token 后存 hash

**效果**：每个 refresh token 只能用一次。攻击者偷到的 token 一旦用过，合法用户下次刷新会发现失效（被盗用信号），触发重新登录。

### 4. logout 不使 token 失效

**位置**：`backend/internal/handler/auth/auth_handler.go:119`（Logout）

**问题**：原 Logout 直接 `resp.Success(c, nil)`，什么都不做。JWT 无状态，登出后 access token 仍有效 15 分钟，refresh token 仍有效 7 天。

**修复**：`auth_service` 新增 `Logout(userID)` 调 `ClearRefreshTokenHash`；`auth_handler.Logout` 调用之，使 refresh token 失效。access token 15 分钟短期可接受。

### 5. nginx 缺安全头部

**位置**：`frontend/nginx.conf`

**问题**：nginx 配置无任何安全响应头，存在点击劫持（X-Frame-Options 缺）、MIME 嗅探（X-Content-Type-Options 缺）、Referrer 泄露风险。

**修复**：server 块加：
```nginx
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```
（HSTS 因 HTTPS 暂未启用，不加）

### 6. nginx 缺上传大小限制

**位置**：`frontend/nginx.conf`

**问题**：nginx 默认 `client_max_body_size` 1MB，博客图片上传（`POST /upload/image`）和头像上传可能超限返回 413。

**修复**：加 `client_max_body_size 10m;`。

## Important 修复（后端）

### 错误信息泄露
**位置**：`backend/internal/pkg/response/response.go`（InternalError）+ ~30 处 handler 调用
**问题**：handler 用 `resp.InternalError(c, err.Error())` 把内部错误（DB 错误、路径、堆栈）直接返回客户端。
**修复**：InternalError 在 release 模式（`gin.Mode`）记日志 + 返回通用 `"internal server error"`；debug 模式保留详细（开发方便）。一处修复影响所有调用。

### 输入长度限制
**位置**：
- `backend/internal/dto/request/comment_req.go`（Content 加 `max=10000`）
- `backend/internal/handler/content/tag_handler.go`（Name `max=64`，Color `max=7`）
- `backend/internal/handler/content/category_handler.go`（Name `max=64`，Description `max=500`）
- `backend/internal/handler/social/guestbook_handler.go`（Content `max=2000`，Nickname `max=128`）
- `backend/internal/handler/content/friend_link_handler.go`（Name `max=128`，URL `max=512`+`url` 校验，Description `max=500`，LogoURL `max=512`）
**问题**：多个请求字段无 max 限制，可提交超长内容，被滥用存储大量数据。
**修复**：加 binding `max` 标签。

### CORS
**位置**：`backend/internal/middleware/cors.go`
**问题**：无 Origin 时返回 `*`；`frontendURL=="*"` 分支允许 AllowAll+Credentials 共存；不匹配 origin 回显 frontendURL；localhost 硬编码进生产白名单。
**修复**：只对白名单 origin 回显（含 `Vary: Origin` + Credentials）；无 Origin 不设头；不匹配不回显；localhost 仅 debug 模式（`gin.Mode != ReleaseMode`）。

### Dockerfile 非 root + 版本锁定
**位置**：`deploy/backend/Dockerfile`、`deploy/frontend/Dockerfile`
**问题**：容器以 root 运行；frontend 用 `nginx:alpine`（latest，不可复现）。
**修复**：backend 加 `appuser` + `USER appuser` + uploads 目录 chown；frontend 锁 `nginx:1.27-alpine`。

### 容器资源限制
**位置**：`deploy/docker-compose.yml`
**问题**：2GB VPS 无 memory limit，容器内存泄漏可能整机 OOM。
**修复**：postgres `512m`，backend `512m`，frontend `128m`。

### CI 不停 postgres
**位置**：`.github/workflows/ci.yml`
**问题**：`docker compose down` 停所有服务含 postgres，部署期间数据库不可用，且重建 postgres 容器有数据风险。
**修复**：改为 `docker compose build --no-cache backend frontend` + `docker compose up -d --force-recreate backend frontend`，postgres 不动。

### 头像删除校验
**位置**：`backend/internal/handler/auth/auth_handler.go`（UploadAvatar）
**问题**：`os.Remove(filepath.Join("uploads/avatars", filepath.Base(oldUser.AvatarURL)))` —— 若 AvatarURL 被篡改（UpdateProfile 允许设任意值），可删 avatars 目录下任意文件。
**修复**：新增 `avatarFilenameRe` 正则 `^\d+_[0-9a-f]{8}\.jpg$`，删除前校验文件名匹配后端生成格式。

### Search 错误日志
**位置**：`backend/internal/repository/blog/blog_repo.go`（Search）
**问题**：`ftsRows, _ := r.db.Query(...)` 和 `likeRows, _ = r.db.Query(...)` 用 `_` 静默忽略错误，数据库异常时搜索静默返回空。
**修复**：改为捕获 `err` 并 `log.Error` 记录。

### ratelimit 内存泄漏
**位置**：`backend/internal/middleware/ratelimit.go`
**问题**：visitor map 只增不减，`lastSeen` 字段存在但未用，长期运行内存累积。
**修复**：`lastSeen` 改 `time.Time` 并在每次访问更新；新增 `cleanup` goroutine 每分钟扫描，删除 3 分钟未见的 IP。

## 前端审查结论

前端审查未发现 Critical/Important 安全问题：

- **XSS**：MarkdownRenderer 用 react-markdown 渲染 markdown 原文（**非** content_html），`dangerouslySetInnerHTML` 仅用于 shiki codeToHtml 输出且经 `DOMPurify.sanitize`（`USE_PROFILES: {html: true}`）。全前端仅 1 处 dangerouslySetInnerHTML（grep 确认）。BlogDetailPage 所有用户数据（title/ai_summary/tags/excerpt）纯文本 React 渲染。后端 `goldmark.New()` 默认转义 HTML（未启用 unsafe），content_html 安全。
- **OAuth**：OAuthCallbackPage 校验 error/code 参数，一次性 code 经后端 `oauthStore.exchange`（消费即删，5 分钟过期），token 不暴露在 URL。
- **路由权限**：AdminLayout 前端守卫（`user.role !== 'admin'` → redirect `/login`）+ 后端 RequireAdmin 中间件，双重防护。
- **token 刷新**：client.ts `refreshing` promise 单例防并发刷新，refresh 失败清 token。
